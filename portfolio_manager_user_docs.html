01Overview

A headless Python CLI portfolio operating system for Schwab accounts. Google Sheets is the user-facing surface and system of record.

CLI owns execution

Python gathers and calculates everything deterministically. Nothing is inferred at read time.

Sheets owns persistence

The spreadsheet is authoritative for anything you look at or edit by hand.

Bundles are immutable

Context is SHA-256 hashed at creation. Agents reason over a frozen snapshot, never live data.

Promotion is manual

AI output lands on sandbox surfaces. Nothing becomes authoritative without you.

Scope. The system tracks three of six Schwab accounts — suffixes 6499, 8767, 5119. Totals it reports are not your full invested assets. Positions exist in the excluded accounts too.

02Daily Workflow

What a normal day looks like end to end.

# 1 — refresh everything (Sheets + bundle + briefing)
python manager.py morning --live

# 2 — if Schwab auth expired
python manager.py login

# 3 — check what broke without running the whole pipeline
python manager.py health --verbose

# 4 — refresh the phone-readable dashboard (static HTML, mirrored to Drive)
python manager.py store publish-cockpit --live --publish

Then read the 0_DASHBOARD tab in the Sheet, and the briefing bundle under exports/ai_briefing_<timestamp>/. For a phone-friendly read, the published cockpit is at the Drive-synced Portfolio_Analysis folder, not pm ui serve — see PortfolioStore & Local UI.

Every write needs --live. Commands default to dry run and print what they would do. dry is the default; --live writes.

A dry run still writes local files (bundles, moment caches, exports) even without --live — only Sheet/SQLite writes are gated. See The Morning Pipeline.

03The Morning Pipeline

python manager.py morning --live runs these in order. Any step can fail without killing the run except the health gate.

  1. Health check — Schwab tokens, Sheet connectivity, bundle age, FMP cache, transactions freshness. A critical failure stops the run; an unattended run (no TTY) writes logs/HEALTH_FAILURE.flag instead of prompting for reauth.
  2. Sync Schwab — transactions and positions, scoped to the three primary accounts.
  3. Update portfolio state — fresh prices, Holdings_Current, Daily_Snapshots.
  4. Freeze market bundle — positions, prices, cash, realized G/L, fundamentals. Hashed.
  5. Batch podcast sync — RSS → transcript → Gemini summary.
  6. Spotify digests — ingests allocation-YYYY-MM-DD.txt from the Studio folder, dedup by sha256. Non-fatal if the folder doesn't exist on this machine.
  7. Extract high-signal moments — cached, position-independent fragment extraction (reversals, non-consensus claims, disclosures) from new transcripts only.
  8. Dislocation scan — flags drawdowns and valuation gaps. Runs before the dashboard step so Crosshairs sees today's payload — 0_DASHBOARD is clear-and-rebuild, so a late scan can't be patched in.
  9. Refresh dashboard — Valuation_Card → Crosshairs → 0_DASHBOARD / Decision_View → Tax_Control → conditional formatting, in one pass.
  10. Sheets → thesis files — writes current allocation, cost basis and transaction logs into vault/theses/. Skips (warns) any thesis with unparseable frontmatter rather than aborting the whole vault.
  11. Freeze vault bundle — thesis files, research, styles.json. Hashed.
  12. Build composite bundle — market + vault + recent rotations. This hash stamps every agent response.
  13. Export AI briefing — writes exports/ai_briefing_<timestamp>/.
  14. Derive rotations — clusters sell/buy pairs into candidates on Trade_Log_Staging. Dry-run within morning.
  15. Publish analysis — copies readable output to the Drive-synced folder.

A dry run still writes to disk. Steps 3 (bundle), 4.5 (dislocation), 4c (moments), and 7–9 (vault bundle, composite bundle, briefing export) create local files regardless of --live. Only Sheet writes are gated, per-step. "Dry run" means Sheets-dry, not no-op — this is a known, deliberately-deferred design gap, not a bug to report.

06Thesis Files

One markdown file per position in vault/theses/. Your reasoning lives here; the pipeline writes the numbers.

---
ticker: RRC
style: THEME              # GARP | THEME | FUND | ETF
entry_date: '2026-08-07'
cost_basis: 3672.70
current_allocation: 0.61%
triggers:
  trigger_type: price_to_book
  price_add_below:
  price_trim_above:
  style_size_ceiling_pct: 3.0
---

Who writes what

PartOwner
Core Thesis, Bull Case, Key Risks, Exit ConditionsYou. Never machine-written.
next_step, priorityYou. Agents may flag, never resolve.
cost_basis, current_allocation, transaction log, sizing regionsSync, on every run.
triggers: blockYou, with computed proposals for sign-off.

[BILL] markers flag a judgment only you can make. They are deliberate placeholders, not omissions — nothing resolves them automatically.

The <!-- region:* --> blocks are sync-managed. position_state, sizing, transaction_log, realized_gl and change_log get rewritten. Don't hand-edit them.

07Trim / Add Triggers

When a position should come back onto your desk. Six types, because one metric across 39 positions is the wrong shape.

TypeBand fieldsUse for
priceprice_trim_above · price_add_belowDeliberate nominal levels. Gold, income funds.
fwd_pefwd_pe_trim_above · fwd_pe_add_belowGARP names with forward-estimate history.
trailing_petrailing_pe_trim_above · _add_belowGARP names where only trailing history exists.
discount_from_hightrim_below_discount_pct · add_above_discount_pctBoring Fundamentals — bought on fear-driven dislocation.
price_to_bookpb_trim_above · pb_add_belowCyclicals, where earnings multiples invert at peak.
ceiling_only—ETFs, thematic bets, and anything without enough history.

Two rules worth internalising

Never peg a trim to a sell-side price target. Consensus targets ratchet — analysts revise up after a stock rises, so the level climbs with the price and can never fire. VST carried price_trim_above: consensus_price_target and it was never once actionable.

Band and trigger must use the same metric. A band built from trailing P/E history and evaluated against a forward reading is broken by a different factor per company — APO trades 45.7 trailing against 12.0 forward, AVGO 71.1 against 21.9. The trim would never fire.

trigger_type is primary, not exclusive. A file can hold populated bands for more than one type. Only the declared type counts toward coverage and drives the dashboard's distance column; the rest stay in the bundle as secondary data.

Bands are computed from each position's own history — never a peer group, never an analyst estimate. Where history is too thin to be meaningful, the answer is ceiling_only, not a manufactured band.

08Rotations & Attribution

The rotation — a linked sell/buy basket with an implicit substitution thesis — is the unit of analysis.

The path

Transactions
   └─ derive_rotations  ─→  Trade_Log_Staging   # candidates, Status = pending
        └─ you set Status = approved
             └─ journal promote --live  ─→  Trade_Log
                  └─ refresh rotations --live  ─→  Rotation_Review

Set Status to approved, not promoted. promoted is what the command writes on success. Typing it yourself makes the row invisible to journal promote — roughly 16 pre-existing rows were found mismarked this way before the 2026-08-08 hardening pass caught it. A real promotion also stamps Promoted_At; a blank timestamp on a promoted row means it was hand-typed.

Reading the attribution

ColumnAnswers
Residual_Pair_NdThe headline. Selection skill after stripping out the risk step-up. You sell low beta and buy high beta, so a raw pair return flatters you in a rising market.
Pair_Return_NdDid the buy beat what you sold to fund it?
Vs_Index_NdDid it beat simply putting the proceeds in VTI? The harsher question.
Sell_Vs_Index_NdDid the funding side go on to lag? Measures the selling instinct separately.
Bench_Spread_NdGap between best and worst benchmark. Wide means the verdict depends on the yardstick.

Treat the aggregate as evidence, not a scorecard. The sample is one market regime, windows overlap heavily so effective N is far below nominal N, and excluded rows are non-random — they skew old and wide. The medians describe well-reconciled rotations, not all of them.

09Podcast Ingestion

Two paths. They are kept separate on purpose.

Path 1 — YouTube

RSS → transcript → Gemini summary. Runs as STEP 4 of the morning pipeline.

Path 2 — Spotify Studio

Drop allocation-YYYY-MM-DD.txt in the Studio transcripts folder. STEP 4b picks it up, dedups by sha256.

Everything in podcasts.md is model output. It is the largest file in the bundle after the prompt payload, and nothing verifies it. The hash proves the bytes haven't changed — not that the content is true.

Every summary carries an invented ## Sector Allocations table, because the template has one. A qualitative interview about assessing management produced "Broad Market, Target 100%, Range 95–105%." That is a fabricated structure, not a reported figure.

Never take a position weight from a digest. One cited JPIE at 4.7% against an actual 0.83%. Read weights from the bundle.

Count a theme once per run. Consecutive daily aggregates repeat each other, and aggregates discuss episodes that are separately ingested in the same window.

A separate high-signal moment pass runs alongside summarization (STEP 4c). extract-moments pulls falsifiable, verbatim fragments — a conviction reversal, a disclosed position, a specific numeric claim — cached per transcript and independent of what you currently hold. Relevance (HELD / THESIS_ON_FILE / ADJACENT / ZERO_EXPOSURE) is computed fresh every time the cache is read, not baked in at extraction time, since the position set changes but the transcript doesn't. Re-run manually with python manager.py extract-moments [--force NAME] [--limit N].

10PortfolioStore & Local UI

A SQLite shadow ledger and a local FastAPI Command Center, built alongside the Sheet — not a replacement for it.

Sheets stays authoritative

STORE_PRIMARY defaults to sheets. SQLite is a verified shadow copy, kept in sync on live writes — nothing flips primacy automatically.

Phase 1 scope only

The ledger covers transactions, realized_gl and tax_control. Holdings_Current stays a morning-refresh cache, not part of it.

Verified to the cent

pm store verify reconciles proceeds, cost, G/L, ST/LT and disallowed-loss between Sheets and SQLite — not just row counts.

Two different UIs

pm ui serve is a localhost debug tool. Phone/remote monitoring is pm store publish-cockpit — a static HTML render mirrored to Drive.

Why a second store exists

The Sheet is fast to hand-edit but has no query language and no integrity check beyond what you notice by eye. core/store/ defines a PortfolioStore protocol with two implementations — SheetsPortfolioStore (reads the live Sheet) and SqlitePortfolioStore (reads the local ledger) — plus a DualStore that writes both and lets reads be compared. This is the infrastructure for an eventual primacy flip; today it exists so drift between the two can be caught early, not to change where you look for the truth.

Verification & the streak gate

ConceptMeans
Value-level verifypm store verify checks Sheets vs SQLite figure-by-figure, not just that the same number of rows exist on both sides.
Ledger hash paritypm store bundle-parity compares a canonical-JSON SHA fingerprint of each side's ledger — the same hashing discipline the bundles use.
StreakSTORE_VERIFY_STREAK_N (default 5) consecutive green verify runs, gated non-vacuous by requiring ≥1 realized lot in the window. Weekends with no run neither advance nor break it.

This is Phase 1 infrastructure, not a finished migration. No command here changes what you should treat as ground truth — that's still the Sheet, until a deliberate, hand-run primacy flip happens later.

11Conventions

The rules the system is built around, and why.

RuleReason
Read-only on brokerageNo order or trading endpoint is imported or called. Ever.
Agents never fetchNot principle — reproducibility. A Python-gathered snapshot is hash-stamped and re-runnable, so when a number turns out wrong you can tell whether the data changed or the reasoning did.
Every write needs --liveEach command enforces its own dry-run default.
No price targets or buy/sell callsIn any agent output. The system surfaces facts and flags; you decide.
AI output never becomes authoritativeIt lands on sandbox surfaces. Promotion is manual. The rule is about promotion, not file location.
Single-batch Sheet writesNever cell-by-cell. Rate limits cause partial writes mid-loop.
Archive before overwriteA .bak taken after an edit is not a backup. Prove pre-edit content by grep.
The file is stale, not the behaviourWhere a thesis file and your trades disagree, the default inference is that the file is out of date. Report it as a documentation task, not a discipline failure.
