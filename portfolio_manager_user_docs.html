System Overview

What this is: A deterministic, headless portfolio control system. It gathers Schwab data, parses it, combines it with manual constraints and research documents, and presents it in Google Sheets. It is the liquid-investments companion to the RE Property Manager.

What this does: It acts as a data orchestration pipeline bridging brokerage data with professional-grade analysis (Frontier LLMs). It creates a deterministic "spine" of truth—prices, technicals, tax lots, and written theses—while delegating qualitative reasoning to strictly sandboxed external models.

What this isn't: This is not an auto-trader, a robo-advisor, or a web application. It makes no trades, possesses no order execution logic, and the UI (Streamlit) has been deliberately removed in favor of Google Sheets visibility.

Architecture Spine

The core structural tenet is simple: CLI owns execution, Sheets owns persistence, visual layer is read-only and replaceable.

Python calculates everything deterministically. LLMs reason only over immutable, hash-fingerprinted context bundles and write to local sandbox markdown files or sandbox sheet tabs.

[ Schwab API ] + [ Local Vault/Theses ] + [ Web Sources ]
        ↓                  ↓                     ↓
[ Python CLI (gathers & computes deterministically) ]
        ↓
[ SHA-256 Canonical Bundles (Immutable JSON) ]
        ↓
[ Google Sheets (Authoritative State / UI) ]  <-- (Manual Interventions)
        ↓
[ Sandboxed AI Agents (Read Bundles -> Write Markdown) ]

Bundle Architecture

The system freezes state into three canonical, SHA-256 hashed JSON bundles. This guarantees LLMs always reason over exactly the same data snapshot.

  • Market Bundle (core/bundle.py): Contains positions, prices, cash, realized G/L, and target allocation snapshots.
  • Vault Bundle (core/vault_bundle.py): Holds research documents, parsed _thesis.md files, transcripts, and strategy/style matrices.
  • Composite Bundle (core/composite_bundle.py): A thin wrapper mapping the Market + Vault bundles, enriched with Tier-2 data (like recent rotations from the Trade_Log tab). Every agent request is stamped with its composite_hash.

Data Sources

  • Schwab Developer API: Read-only access to account data and transactions. The primary truth path.
  • CSV Fallback: Retained for disaster recovery and realized G/L historical imports.
  • Market Data: yFinance (prices, sector, dividend yield, beta), FMP (fundamentals via fmp_client.py), Finnhub.
  • Podcasts: Transcript ingestion via established pipeline (cron/manual triggers) into the local Vault.

Operating Principles

Fire-fire-aim, not NASA. We ship minimum viable agents, learn from real output, and iterate.
  • LLMs synthesize, APIs calculate. Python math is deterministic. LLMs do not do math.
  • Read-only on Brokerage. The system has zero capability to trigger buys or sells.
  • Agents never browse or fetch. Python gathers context; LLMs reason within that box.
  • DRY_RUN defaults true. No writes happen to the Sheet without the --live flag.
  • Single-batch gspread writes. Always write with fingerprint deduplication, never cell-by-cell.
  • Archive-before-overwrite. All pipeline writes backup prior state.
  • Bundle immutability. Bundles are SHA-256 hashed. Every agent response carries a composite_hash.
  • No predictions. Agents explicitly do not provide price targets, buy/sell commands, or definitive market predictions.

Agent Layer

The agent layer is actively being built out in a read-only, local-markdown-first methodology. Agents interact via utils/gemini_client.py enforcing ask_gemini_composite() tracing.

Idea Generator v1 (Active)

Consumes podcast transcripts and recent research from the Vault Bundle, applies strategy classification (matching the 4 core styles), and generates structured candidate profiles. It detects portfolio overlaps but respects the "no explicit buy recommendation" rule.

Invocation: python manager.py agent ideas [--since-days 7]

Output: Local markdown file in agent_outputs/ideas/.

Valuation Drift Monitor (Next)

A planned sell-side signal generator. It will track changes in fundamentals (forward P/E, PEG, dividend coverage) against the original baseline stored in an asset's _thesis.md. Will alert on "thesis drift" without demanding a sell.

Tax Architecture

The tax layer consists of the RealizedGL CSV ingestion and the Tax_Control computed view.

It utilizes current YTD realized gains/losses plus configured tax rates from config.py. This data acts as a constraint mechanism for future agents (like the Drift Monitor) to avoid punitive short-term taxation unless thesis-violation criteria are met.

Automation

  • Podcast Sync: Runs via a GitHub Actions cron job every Friday at 5:00 PM EST (also accessible via workflow_dispatch).
  • Token Keep-Alive: A GCP Cloud Scheduler/Cloud Function pair pings the Schwab API every 25 minutes during market hours to prevent the 7-day token expiration from lapsing. (GCP Project: re-property-manager-487122)

What is Explicitly Out of Scope

The May 2026 reframe dropped multiple legacy components to focus the pipeline:

  • Streamlit Cloud / Web UIs: Completely abandoned in favor of Google Sheets + CLI.
  • The "Nine-File Agent Kit": Specifically, the Re-buy Analyst, Add-Candidate Analyst, New Idea Screener, and List Coherence Checker are deprecated. Their value was absorbed into the broader Idea Generator pattern or deemed unnecessary.
  • Auto-Trading: A hard ban. Read-only API access forever.
  • MCP Integrations / Gemma: Deemed unnecessary for this server-side pipeline.
