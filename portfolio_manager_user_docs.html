1. System Overview

What this is

A headless Python CLI portfolio operating system. It pulls live position data from the Schwab API, freezes that data into immutable SHA-256-hashed JSON bundles, enriches it with yFinance and FMP fundamentals, writes computed views to Google Sheets, and exposes AI agents that reason over those frozen bundles. Every run is deterministic and auditable. No state leaks between runs.

What it does

On any given morning: runs a health check against Schwab tokens and APIs, syncs transaction history, freezes current holdings and prices to a bundle, rebuilds all computed Sheet views (Dashboard, Valuation Card, Decision View, Tax Control), and optionally runs agents that surface investment candidates or flag valuation drift. All writes to Sheets require an explicit --live flag. Everything else is a dry run by default.

What it is not

Not an auto-trader. Not a robo-advisor. Not a backtest framework. Not a web app. The system never places orders, never calls Schwab order endpoints, and never makes autonomous decisions. LLMs synthesize; the investor decides.

2. Architecture Spine

Three layers, each with a defined role:

  • CLI owns execution. manager.py (Typer app) is the single entry point. All operations are explicit, logged, and deterministic.
  • Sheets owns persistence. Google Sheets is the authoritative frontend. The CLI computes; Sheets stores. No other UI is authoritative.
  • Bundles own context. Every agent run starts from a frozen, hash-verified JSON bundle. Agents never browse, never fetch live data, and never write to production tabs directly.

4. Bundle Architecture

Bundles are the system's memory. Every agent run starts from a verified frozen bundle. No agent calls live APIs. No agent writes to production tabs.

Market bundle (context_bundle_*.json)

Built by core/bundle.py. Snapshot of holdings, prices, tax lots, enrichment metadata. Hash function: _sha256_canonical() applies SHA-256 to a canonical JSON serialization of the payload (sorted keys, no whitespace, ASCII-safe). The hash excludes the bundle_hash field itself via _hashable_payload(). Data sources: Schwab API primary, CSV fallback. Enriched with yFinance, FMP, technicals, and style classification.

Vault bundle (vault_bundle_*.json)

Built by core/vault_bundle.py. Snapshot of all thesis files, podcast transcripts, and research notes from the local vault/ directory. Each document is individually hashed with _sha256_text() over its UTF-8 bytes. The bundle hash wraps all document hashes. Drive fallback is not yet implemented. Currently covers 62 thesis files.

Composite bundle (composite_bundle_*.json)

Built by core/composite_bundle.py. A thin metadata object linking market and vault bundles. Adds Tier 2 data: top-10 recent rotations from the Trade_Log Sheet tab. Composite hash is SHA256(market_hash + vault_hash + recent_rotations_json). Agents interact exclusively with the composite hash for end-to-end traceability.

Hash verification

All three bundle types verify their hash on load. Any tampered field causes an exception before the agent sees data. Verify manually with pm bundle verify <path>.

7. Operating Principles

These are the confirmed hard rules — each has enforcement in code, not just documentation.

RuleEnforcement
Read-only w.r.t. Schwab. No order endpoints ever. utils/schwab_client.py and cloud_functions/token_refresh/main.py both carry explicit prohibited-method lists in their docstrings. Auditable via grep.
DRY_RUN default true. Every write path requires --live. Every write command in manager.py checks if not live: print DRY RUN; return before any Sheet call.
Bundle-first. Agents reason over immutable, hashed snapshots. _sha256_canonical() computed last in build; verified first on load. Hash mismatch raises ValueError before agent sees data.
bundle_hash in every agent output schema. End-to-end audit trail. ask_gemini_composite() raises ValueError if bundle_hash is absent from the Pydantic response schema.
No automated LLM calls against production tabs. All agent output lands in agent_outputs/*.md (local) or Agent_Outputs sandbox tab. Target_Allocation and Config are never written by agents.
Single-batch gspread writes with fingerprint dedup. Append tabs use append_rows() with a Fingerprint column. Never cell-by-cell.
Fire-fire-aim development. Ship minimum viable agents, run on real data, iterate based on real output. The bundle layer keeps the discipline. See Idea Generator v1 as the template.
No price targets, no market predictions, no buy/sell recommendations in agent output. SAFETY_PREAMBLE constant in utils/gemini_client.py line 38 is prepended to every LLM system instruction.

8. Agent Layer

Idea Generator v1 Shipped 2026-05-26

Consumes the composite bundle plus recent podcast transcripts. Extracts actionable investment candidates and classifies each by style fit (GARP, Thematic, BoringFundamentals, SectorETF, Unclear). Flags overlap with current holdings and notes concerns raised by the speaker.

How to run:

pm agent ideas                          # auto-detects latest bundle + 7 days of transcripts
pm agent ideas --since-days 14          # look back further
pm agent ideas --dry-run                # print to stdout, do not write file

Prerequisites: A composite bundle must exist in bundles/. Run pm snapshot then pm vault snapshot then pm bundle composite if no composite bundle exists. Transcripts must be present in data/podcast_transcripts/; run pm ingest podcasts --live to fetch them.

Output: Markdown report written to agent_outputs/ideas/ideas_{YYYY-MM-DD}_{hash_prefix}.md. Filename includes the composite bundle hash prefix for traceability. Output is local only — not pushed to Sheets in v1.

Key files:

  • utils/agents/idea_generator.py — Pydantic schemas (Candidate, IdeaGeneratorOutput), run_idea_generator(), write_idea_report()
  • prompts/idea_generator.md — system prompt describing the investor's four styles and extraction rules

Hard rule compliance: No price targets, no buy/sell recommendations. SAFETY_PREAMBLE is prepended automatically. bundle_hash is required in IdeaGeneratorOutput and verified after the LLM call.

Valuation Drift Monitor Next, not yet built

Sell-side signal generation. Will track changes in forward P/E, PEG, and three-statement quality across current holdings vs original thesis baseline. Flags positions where valuation has materially drifted. Output: markdown report in agent_outputs/drift/. No automatic sell signals — surfaces "worth re-examining" only.

Following the same fire-fire-aim pattern as Idea Generator: ship minimum viable version, learn from real output, iterate.

9. Tax Architecture

Tax state is split across three locations:

  • Realized_GL tab — Append-only log of closed lots from Schwab CSV import. Contains: ticker, closed date, opened date, proceeds, cost basis, gain/loss, term (ST/LT), wash sale flag, disallowed loss.
  • Tax_Control tab — Computed view rebuilt by pm refresh tax --live. KPI strip (Net ST, Net LT, wash sale drag, estimated Fed cap gains tax, offset capacity) plus a lots table sorted with wash sale lots pinned to top.
  • Config tab — Manual: ST/LT tax rates, rebalance threshold, TLH threshold. Read by the pipeline; never written.

To run tax-rebalance analysis with an external LLM:

pm export run tax-rebalance

This builds a package in exports/ containing prompt.md and context.json with TLH candidates, unrealized gains, and wash sale lots. Paste prompt.md into Claude or Gemini and attach context.json.

  • What it does: runs python tasks/batch_podcast_sync.py --live, commits updated data/processed_videos.json dedup log back to repo

GCP Cloud Function — Schwab token refresh

File: cloud_functions/token_refresh/main.py

  • Triggered by: GCP Cloud Scheduler, every 25 minutes during market hours
  • What it does: calls Schwab's get_account_numbers() (read-only) to trigger schwab-py's automatic token refresh; stores fresh token in GCS bucket portfolio-manager-tokens
  • Safety: explicitly prohibited from placing orders (docstring enforced by grep)
  • Project: re-property-manager-487122 (shared with RE Property Manager)
