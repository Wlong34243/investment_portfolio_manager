**Executor:** Cursor (Agent mode). Claude Code / Gemini CLI also acceptable.

**Gates:** nothing.

> **No LLM call anywhere in this prompt.** The model's job ended at extraction, in prompt 2. This is
> a compiler: it reads structured extraction, joins it against the held position set, counts, and
> writes JSON. Every number on the resulting tile is arithmetic over fields a model wrote about a
> *video*, never a model's opinion about a *portfolio*. If a step here feels like it wants a Gemini
> call, that step is out of scope.

## Three corrections to the blueprint, before any code

**1. There is no frontmatter. Read the JSON sidecar.** Prompt 2's brief is markdown with a header
block and prose sections; the structure lives in the `.json` sidecar written beside it
(`model_dump()` of `AIResearchBrief`). Parsing model-written markdown to recover fields that are
already sitting in a JSON file next to it is a fragile step for zero gain. **The `.md` is for
humans; the `.json` is the interface.**

**2. `ticker_aliases.json` is a vocabulary, not the portfolio.** It maps 548 S&P 500 names to
tickers. Intersecting `named_orgs` against it tells you a *listed company was mentioned* — it says
nothing about whether Bill owns it. Exposure requires a second input: the held set, via
`retrieve("holdings_current", {})`. Skip this and the tile reports MU as "Exposed" because MU is in
the S&P 500, which would be true of 500 tickers and useful for none.

**3. Two buckets are not enough — and the third is the valuable one.** The blueprint's example,
`Zero-Exposure: ARM (2), OpenAI (7)`, quietly merges two different facts. ARM is a listed company
Bill could buy tomorrow (and is *absent from the alias map*, so today it would not even be detected).
OpenAI is private and cannot be held at all. Collapsing them produces a "zero-exposure idea" that is
not investable. Three buckets:

| Bucket | Meaning | Why it matters |
|---|---|---|
| `exposed` | Matched a ticker in `holdings_current` | You own the thing being discussed |
| `listed_unheld` | Matched the alias map, not in holdings | Investable. This is the zero-exposure idea surface |
| `unlisted` | Named entity matched nothing | Mostly private AI labs. **Not investable directly** — the signal is second-order, and the tile must not imply otherwise |

Plus a fourth output that is not a bucket but a maintenance queue: **`unmatched_entities`**, every
`named_org` / `named_system` string that matched nothing, with counts. That list is how the alias map
gets extended, and it is the only honest way to discover that "SK Hynix" resolved but "Arm Holdings"
did not.

## Design decisions, already made — do not relitigate

**No dependency on the AI Watch run.** The blueprint says "runs after `ai_watch_analysis`". It should
not. The index reads briefs; AI Watch also reads briefs. Chaining them means the tile goes stale
whenever the weekly Gemini run is skipped, for no benefit. Independent, and cheap enough to rebuild
on every dashboard refresh.

**`data/ai_thematic_index.json`. Not a bundle, not hashed, not immutable.** In this repo "bundle"
means SHA-256-stamped context that agents reason over, and `composite_hash` stamps every agent
response. Borrowing that vocabulary for an unverified thematic index invites someone — a person or a
future agent — to treat it as carrying the same guarantees. It is a cache. It is overwritten whole on
every run. It is regenerable from `data/ai_briefs/` in under a second.

**Writing it requires `--live`.** Hard Rule 3. Dry run prints the JSON and writes nothing.

**The tile is read-only and degrades to absent.** Missing or malformed index file → the cockpit
renders the panel with a "no AI index — run `pm ai index --live`" line, not a stack trace and not a
silently empty panel that looks like "no activity".

**This one *is* eligible for the desk launcher, and ai-watch was not.** The 2026-08-28 policy admits
routines that write regenerable computed surfaces. A deterministic recompile of a disposable JSON
from local files, with no broker call and no Gemini call, is squarely that — unlike `ai-watch`, which
is a batch model recompute. Register it in `ui/routines.py` **without** typed-confirmation: it is not
a clear-and-rebuild of a tab Bill reads, it is a cache refresh. State this reasoning in the routine's
registry comment so the next reader does not have to re-derive it.

## Step 1 — `utils/build_ai_index.py`

```python
def build_index(days: int | None = None) -> dict      # pure; no writes
def write_index(index: dict, live: bool = False) -> Path | None
```

`build_index` reads every `data/ai_briefs/*.json` (optionally windowed by the date in the filename),
and for each brief emits an entry:

```json
{
  "brief_path": "data/ai_briefs/2026-08-29_Google_DeepMind_....md",
  "video_url": "https://www.youtube.com/watch?v=...",
  "channel": "Google DeepMind",
  "date": "2026-08-29",
  "headline": "...",
  "novelty": "new_result",
  "source_quality": "High",
  "named_figure_claims": 4,
  "qualitative_claims": 3,
  "exposed":        [{"ticker": "MU", "matched_on": "Micron Technology"}],
  "listed_unheld":  [{"ticker": "AVGO", "matched_on": "Broadcom"}],
  "unlisted":       ["OpenAI", "Anthropic"],
  "verified": false
}
```

plus a top-level roll-up over the window: totals by `novelty`, total `named_figure` claims (the
"unverified figures" count), per-ticker mention counts across all three buckets, channels with zero
briefs, and `unmatched_entities`.

**Matching rules — mechanical, and deliberately conservative:**

- Reuse `utils.moment_windows.load_ticker_aliases` and its `_word_pattern` / `_alias_patterns`
  helpers. Do not write a second matcher. If those helpers are private, promote them rather than
  copying them.
- Match against the brief's `named_orgs` and `named_systems` **lists only** — never the free-text
  `summary` or `claims`. Prose matching is where false positives live ("Apple" in "apples to
  apples"), and the extraction lists exist precisely so this step does not need prose.
- Word-boundary, case-insensitive, whole-alias. No substring, no fuzzy, no stemming. A miss goes to
  `unmatched_entities` where Bill can see it; a false match is invisible and lands on the cockpit.
- **Bare-ticker aliases stay excluded where the alias file excludes them.** `load_ticker_aliases`
  strips `_`-prefixed keys and the file documents deliberate omissions for common-word collisions;
  honor that file, do not re-add them.
- `exposed` vs `listed_unheld` is decided by the ticker set from
  `retrieve("holdings_current", {})`. **Ledger reads go through `core/retrieval` — do not open the
  DB here.**

`verified` is `false` for every entry until a verification sidecar exists for that brief's
`transcript_sha256` (prompt 4, Step 4). Compute it by looking for the sidecar; do not trust a field
in the brief.

## Step 2 — `data/ai_entity_aliases.json`

A hand-maintained supplement, loaded and merged over `ticker_aliases.json` at build time. It exists
because the S&P 500 generator cannot produce it: `ARM` is not in the map, `SKHY` resolves only on
"SK Hynix", and no AI-native name resolves at all.

Two sections:

```json
{
  "_comment": "Hand-maintained. Supplements data/ticker_aliases.json for the AI track only.",
  "tickers":  { "ARM": ["Arm", "Arm Holdings"], "SKHY": ["SK Hynix", "Hynix"] },
  "unlisted": ["OpenAI", "Anthropic", "Google DeepMind", "DeepMind", "Mistral", "xAI"]
}
```

`unlisted` is an explicit allowlist so a known private lab lands in the `unlisted` bucket rather than
in `unmatched_entities`. **Seed it from the first real run's `unmatched_entities` output, not from
this prompt's imagination.** Ship the file with the two ticker entries above and an empty `unlisted`
list; Bill fills it after seeing real data.

**Do not merge these entries into `data/ticker_aliases.json`.** That file is generated by
`scripts/generate_ticker_aliases.py` and hand edits would be destroyed on the next regeneration.

## Step 4 — Cockpit tile

Read-only render of the index file in `ui/app.py`'s cockpit. Follow `ui/header_context.py`'s existing
cache pattern — 60s TTL, invalidated on the index file's mtime, missing file as a `None` sentinel
with TTL-only expiry.

Panel contents, and nothing beyond them:

- **Catalyst** — `headline`, linked to the local `.md` brief via the existing `/doc/{id}` route if
  the brief is corpus-indexed (prompt 4 registers it), else a plain path.
- **Evidence** — `"2 new results · 11 unverified figures"` from the roll-up counts.
- **Mentions** — `Exposed: MU (3)` · `Listed, unheld: AVGO (2)` · `Unlisted: OpenAI (7)`, the three
  buckets visually distinct and **labelled**, never merged into one "zero-exposure" line.
- **Quiet** — channels with zero briefs in the window.

**Every row carries a model-output provenance marker**, consistent with `ui/corpus_search.py`'s
badges. This panel sits on the same screen as holdings and market values; without a badge it inherits
their apparent authority, which is the mechanism that let a wrong JPIE weight travel.

**Forbidden in this panel, permanently:** any impact or adjacency claim, any horizon or timeframe,
any sector attribution, any ordering that implies importance to the portfolio, any color coding
shared with the portfolio's gain/loss palette. A mention count is a fact. "Likely to be impacted" is
a forecast, and no field in the pipeline supports one.

## Out of scope — do not build

- Any impact, adjacency, sector-attribution or horizon field, in the index or the UI. This is the
  boundary the whole prompt exists to hold.
- Any LLM call.
- Ranking briefs by portfolio relevance. Sorting by "most relevant to holdings" is an implied
  recommendation wearing a sort order. Sort by date.
- Alerts, thresholds, or "N mentions this week" notifications. A count crossing a number is not an
  event until Bill says it is.
- Writing anything to a Sheet or into the composite bundle.
- Auto-extending `ai_entity_aliases.json` from `unmatched_entities`. The queue is for Bill to read;
  an auto-extender would silently invent mappings.
